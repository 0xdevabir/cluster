# Cabling Guide

Phase 03 Task 6. Standards for every physical run; the run list itself is generated by `tools/gen-cable-list.py` from `inventory/network/switch-ports.yaml` + `inventory/racks.yaml`.

| Aspect | Standard |
|---|---|
| Media choice | **DAC** ≤ 3 m (cheap, low power, low latency); **AOC** 3–30 m; optics + fiber > 30 m |
| Color code | 🟦 Blue = cluster (VLAN 200) · 🟥 Red = RDMA (VLAN 400) · 🟩 Green = storage (VLAN 300/301) · ⬜ Grey = management (VLAN 100) · 🟨 Yellow = uplink |
| Labeling | **Both ends**, every cable: `<switch>:<port> ↔ <node>:<iface>` |
| Bend radius | ≥ 10× cable diameter for DAC; ≥ 30 mm for fiber. Violating this on DAC causes intermittent CRC errors that look like a bad transceiver. |
| Slack | 300 mm service loop at the node end |
| Routing | Never across the front of a chassis (blocks airflow and service access) |
| Verification | After install: `ethtool <if>` shows the expected speed; LLDP neighbor matches `switch-ports.yaml` |

## M1 run list

All 8 M1 hosts sit in the same rack (`r01`, U1–U8) as the leaf switches (`r01-leaf-a`/`r01-leaf-b` at U39/U41) and mgmt switch (`r01-mgmt` at U38) — every data-plane and mgmt-plane run at M1 is **intra-rack**, so every run is DAC. `tools/gen-cable-list.py` computes each run's U-distance from `inventory/racks.yaml` + node `spec.location.u`, assigns DAC for anything ≤ 3 m (all of M1) and flags anything longer for AOC review (relevant from M2 onward, once inter-rack or longer intra-rack runs appear).

📊 **LLDP is ground truth.** Phase 14 runs an automated check comparing each node's LLDP neighbor to `switch-ports.yaml` and flags any mismatch. Miscabling at scale is a certainty, not a possibility — automate the detection rather than trusting the paper plan.
